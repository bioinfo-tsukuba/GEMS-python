### L6の条件について

これは著者がDiscussionに挙げた限界ではなく、p.1414の命題・証明を読んだ今回の分析である。
証明は履歴の同値類を状態集合 `Q` にするが、観測文字の種類が有限であっても、
区別すべき履歴の種類が有限とは限らない。

たとえば観測文字が `a,b` の2種類だけでも、履歴が `a^n b^n`（`n >= 1`）のときだけ
特定の操作を出す決定的方策を考えられる。履歴 `a^n` と `a^m`（`n != m`）は
続きを `b^n` にすると出力が異なるため、互いに異なる同値類になる。
したがって無限個の同値類を要し、有限文字と決定性だけでは有限の `Q` を導けない。

一方、現行のState関数はDataFrameに保存した観測履歴を読める。
**有限個の制御状態を使う実装が有用であることと、外部履歴を含む全判断が純粋な
有限DFAに縮約できることは同じではない。** 特定のプロトコルを否定するものではない。
有限個の履歴要約で判断できることを追加前提にする、または履歴付き状態機械として
説明するのが方針となる。POMDP全般の不確実性や最適制御をDFAだけで解決するとはしない。

## 4. 方針の優先順位

以下は初回分析時点の提案であり、ユーザー指定ではない。
追加の意向ではL8の決定的な規模評価計画、I1の意味の確認、L2の試験機能案を詳しく検討する。
どの項目も今回の実装依頼にはなっていない。

1. **I1・I2**：旧方式の実機ID重複と残存5テストエラー。再現があり、変更範囲と完成基準を絞れる。
2. **L9・I9と保存の途中停止対策**：実機再開・障害処理が必要な運用では、装置状態照合と保存世代の整合性を先に整える。
3. **L2**：試料分割・系譜管理。論文が明記する機能不足で、親子履歴と一括登録の仕様が必要。
4. **L1**：宣言形式・テンプレート・検証からGUIへ進む。専門知識や科学的条件の判断は残る。
5. **L3・L5・L8、I3・I5・I6**：依存・時間窓等は実際の要件から追加し、大規模評価・実測較正を進める。

L6の理論上の適用条件は文書で先に明確にできる。
旧JSONにない情報、失われた試料、科学モデルの妥当性は「実装で全部解決する」計画に含めない。

### 再現コマンド

依存を導入したPythonで、作業ツリーに生成物を出さずに実行する。
以下は今回確認したcommitを固定している。

```bash
review_dir=$(mktemp -d /tmp/gems-limitations-recheck-XXXXXX)
git archive aee423c0d7c78fd2a34062036669c1dad6164931 | tar -x -C "$review_dir"
cd "$review_dir"
PYTHONPATH="$review_dir" MPLBACKEND=Agg MPLCONFIGDIR=/tmp/gems-mpl \
  /tmp/gems-venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

同じarchive内で、旧割当の固定ケースを確認する。
`run_manager`は各方式を呼び、機械IDごとに重複を独立評価する。
既存設定はCP-SATが5秒・worker 1・seed 0、SAが100,000ステップ。

```bash
MPLBACKEND=Agg MPLCONFIGDIR=/tmp/gems-mpl /tmp/gems-venv/bin/python - <<'PY'
import contextlib, io, tempfile
from pathlib import Path
from scripts.compare_schedulers import make_case, run_manager

for method, seed in [("o", 0), ("f", 0), ("s", 0), ("s", 1), ("s", 2)]:
    with tempfile.TemporaryDirectory() as directory:
        with contextlib.redirect_stdout(io.StringIO()):
            lab = make_case("multi_interval", "LinearPenalty", Path(directory))
            result = run_manager(lab, "multi_interval", method, seed)
        print({key: result.get(key) for key in
               ("method", "seed", "status", "timing_penalty", "overlap_minutes",
                "assignment_errors", "interval_errors")})
PY
```
