# Issue: Experiment作成を容易にするGUI最小構成の実装

## 背景
現状は`mode.txt`や`mode_add_experiments.txt`などのテキストファイル操作で実験を管理しており、初回利用者には操作負荷が高い。  
設定漏れや記述ミスにより、実験追加や実行前確認で手戻りが発生しやすい。

## 目的
Experiment作成から実行前検証までをGUIで一貫して行えるようにし、作成時間短縮と設定ミス削減を実現する。

## 対象範囲（最小構成）
次の6機能を対象とする。

1. Experiment作成ウィザード
2. 状態遷移の可視化エディタ
3. 入力バリデーション
4. シミュレーション実行ボタン（`simulate` / `simulate_one`）
5. マシン管理画面
6. 実験一覧とフィルタ

## 対象外
- 認証、権限管理
- マルチユーザー同時編集
- 外部サービス連携（通知、分析基盤連携）
- 履歴監査の高度化（差分比較UI、承認フロー）

## 完了条件
- GUI上で新規Experimentを作成し、保存できる。
- 状態と遷移をGUIで編集し、未定義状態や不正遷移を保存前に検出できる。
- 実行前にシミュレーションを起動し、結果とエラーを画面で確認できる。
- マシン追加・削除・一覧表示がGUIで行える。
- 実験一覧を状態で絞り込み、名称で検索できる。
- 主要操作に対してテスト（単体テストまたは結合テスト）が整備される。

## 想定成果物
- GUIエントリーポイント
- Experiment作成関連UIコンポーネント
- 状態遷移編集ロジック
- バリデーション層
- シミュレーション実行連携
- マシン管理UI
- 実験一覧UI
- テストコードと利用手順ドキュメント
