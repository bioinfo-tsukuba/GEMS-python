# Scheduler-only pattern study

この文書は `scripts/study_scheduler_patterns.py` が集計した結果です。
旧方式は公開APIの焼きなまし `s`、新方式は OR-Tools `o`。
スケジューリングのみを実行し、シミュレーターは呼んでいません。

## 再実行

```bash
MPLCONFIGDIR=/tmp/gems-mpl poetry run python scripts/study_scheduler_patterns.py \
  --output-dir /tmp/gems-pattern-study-recheck --seeds 0 1 2
```

スクリプトがCSV/JSONとこの要約・図を新しい出力先に生成する。
保存済みの実行別JSONから集計だけを再計算する場合:

```bash
MPLCONFIGDIR=/tmp/gems-mpl poetry run python scripts/study_scheduler_patterns.py \
  --from-runs /tmp/gems-pattern-study-recheck/runs.json \
  --output-dir /tmp/gems-pattern-study-reanalysis
```

[実行可能な対のスコア散布図](paired_scores.png) と[実行可能率・実行時間の図](feasibility_runtime.png)。

## 実行条件

- Python 3.14.4, OR-Tools 9.15.6755, simanneal 0.5.0, Matplotlib 3.11.2。
- 実行環境: Linux-6.18.54.1-microsoft-standard-WSL2-x86_64-with-glibc2.43。
- ケース数 64。焼きなましシード: [0, 1, 2]。
- CP-SAT: 5.0秒制限、1ワーカー、シード0。 焼きなまし: 10万ステップ、Tmax 25000、Tmin 1（既存実装）。
- 各方式の入力は毎回作り直し、スケジュール前のSHA-256が同じことを検査。
- 単一タスク型は4/8タスク、1機械。グループ型は3/6グループで、各グループに2タスク。複数機械型は同タイプの機械を1/2台。
- 最適開始時刻は12分から一定間隔。単一タスク型の集中/分散は2/8分間隔、単一機械グループ型は3/14分間隔、複数機械グループ型は2/8分間隔。処理時間と先行間隔の生成式はスクリプトに固定。
- ペナルティ構成は Linear、Range、Rest+Linear の各単独型と、全5型を順番に使う Mixed。係数・休止周期は `scripts/compare_schedulers.py` の `make_penalty()` に固定。
- 以上のパターン数・間隔・シードは比較のために選んだ合成条件であり、実験運用データから推定した値ではない。

## 指標

- スコアは各タスク/グループの既存 `calculate_penalty()` の合計。低いほどよい。資源制約と割当・先行間隔を満たす実行だけをスコア比較する。
- `CP低点/同点/SA低点` は同一ケース・シードの実行可能な対について数える。スコア差は `SA − CP` で、正ならCPが低い。90%点は最も近い順位の値。
- CPの `OPTIMAL` と `FEASIBLE` を区別する。実行時間はスケジューリング呼出しの壁時計時間。

## 結果

- CP: 64件で最適証明、0件で時間内の実行可能解、0件は実行不能または失敗。
- 焼きなまし: 168/192実行が実機ID単位で実行可能。
- 実行可能な168対のうち、CP低点 110、同点 58、SA低点 0。
- ケース単位で焼きなまし3シード中の実行可能な最良値と比べると、56ケースでCP低点 35、同点 21、SA低点 0。残り8ケースは焼きなましの実行可能解がない。
- スコア差中央値 17.00、90%点 1,000,021。
- 壁時計時間中央値: CP 0.006637秒、焼きなまし 3.587091秒。

## 条件別の観測

- 集中条件は実行可能な72対のうちCP低点71対、分散条件は96対のうちCP低点39対だった。
- 複数機械型の焼きなまし実行可能率は、同型機1台で48/48、2台で24/48だった。
- 全体のスコア差90%点には、開始時刻が休止範囲に入るごとに100万点となる循環休止ペナルティが影響する。線形型・範囲型は上の構成別表で別に確認する。

## 読み方と制約

焼きなましで実機IDが重複するスケジュールの低いスコアは、実行可能な解として勝敗へ加えない。CP-SATが時間制限内に最適証明できなかったケースは、得た解のスコア比較だけに使う。
合成入力と少数の乱数シードによる1環境の結果であり、一般的な速度・解品質の保証や実細胞培養の予測ではない。

再実行時にはCSV/JSONを新しい出力ディレクトリへ保存し、この要約と図を生成結果と照合する。生データをGitに追加しなくても、生成スクリプト、入力SHA-256、条件、集計式を追跡できる。
